## 2. `bin-01` : la promesse fausse est réparée (prouvé hors image)

**Constat d'origine** : la room promettait un shell root. Le binaire ne
contenait aucun chemin vers un shell (`strings` : zéro `/bin/sh`, `objdump` :
aucun `system`, aucun `execve`). Aucun élève ne pouvait obtenir le drapeau par
l'exploitation.

**Réparation** : la lecture se fait par `read()` dans un tampon de 64 octets,
et le programme contient désormais une fonction `carnet_root` — jamais appelée
par le cours normal — qui remet les identités à zéro puis ouvre un shell.

**Preuve** (reproductible en une commande) :

```
$ cd labs/bin-01/src && make
$ cd ../../.. && python3 tools/recette-apprenants/exploit-bin01.py \
      labs/bin-01/src/vulnerable --commande "id; echo SECA-SHELL-OK"
carnet_root      : 0x0000000000401196
bourrage retenu  : 88 octets
...
> uid=1001(user) gid=1001(user) groups=1001(user),27(sudo),100(users)
SECA-SHELL-OK
IDENTITE DU SHELL : pas root (normal hors image : le binaire doit etre setuid root)
```

**Ce qui reste non prouvé** : le shell **root** et la lecture de
`/root/flag.txt` (`FLAG=SECURA{buffer_overflow}`). Cela exige l'image Docker,
donc la mesure GitHub (§4). Hors image, le binaire n'est pas setuid : le shell
s'ouvre avec l'identité de l'utilisateur.

Le contrôle machine correspondant a été remplacé : il ne se contente plus de
lire le drapeau en root (ce qui ne prouvait rien), il exécute
`tools/recette-apprenants/exploit-bin01.py` **dans le conteneur** et exige le
drapeau en sortie.

## 3. Anglais : le chiffre réel, et il n'est pas bon

Mesure sur les 52 rooms installées, champ par champ (titre de tâche, corps de
tâche, énoncé, indice, explication de chaque question) :

```
$ PHPRC= php tools/wp-cli.phar --path=<wordpress> eval-file \
      tools/recette-apprenants/mesure-anglais.php
Champs de texte contrôlés : 1574
Champs encore en français : 0
Champs sans traduction    : 1298
VERDICT : l'anglais n'est PAS terminé — 1298 champs sans traduction,
          0 champs restés en français, sur 1574 contrôlés.
```

Traduction en clair : **les titres et les résumés sont en anglais, le contenu
ne l'est pas.** Le corps des tâches, les questions, les indices et les
explications sont encore en français. Les 31 tâches qui n'ont aucune
traduction du tout représentent, à elles seules, environ **31 600 mots**
(189 517 caractères mesurés).

**Aucune room n'était complète** avant ce soir. Deux le sont maintenant :
`univ-21` (de la donnée au programme) et `avance-14` (révision des labs
avancés), soit **68 champs**. Il en reste **1298**, sur 50 rooms.

C'est un travail éditorial, pas une case à cocher. Annoncer « le site est en
anglais » aujourd'hui serait faux, et c'est exactement le genre d'annonce que
l'audit reproche au développeur précédent.

### La chaîne, pour que ce soit vérifiable et rejouable

| Fichier | Rôle |
|---|---|
| `tools/recette-apprenants/mesure-anglais.php` | mesure champ par champ, code de sortie non nul tant que ce n'est pas fini |
| `tools/traduction/exporter.php` | exporte une room (français de référence + anglais à remplir) |
| `content/en/*.en.json` | **la source de vérité**, versionnée : la base n'est qu'une projection |
| `tools/traduction/importer.php` | applique une traduction, **refuse** tout fichier incomplet |
| `tools/traduction/appliquer-tout.sh` | réapplique toutes les traductions d'un coup |

L'importeur refuse d'écrire si un seul champ est vide ou identique au
français : une room à moitié traduite donne l'illusion d'être terminée, ce qui
est pire qu'une room non traduite.

## 4. Ce que je ne peux pas faire d'ici, et qui ne dépend que d'un clic

Le bac à sable n'a ni Docker ni droit de lancer un workflow (l'API répond
`HTTP 403 : Resource not accessible by integration`). La mesure sur
environnement réel — vrai WordPress, vrais conteneurs, vrai drapeau root de
`bin-01` — doit donc être lancée depuis l'onglet **Actions** du dépôt :

1. ouvrir **Actions** → **WordPress — recette et compatibilité** ;
2. **Run workflow** → branche `arena/a792cc4e-secura-academy` → **Run** ;
3. dans les journaux, chercher la ligne
   `scénario 9 : l'exploit obtient un shell root et lit le drapeau`.

Tant que ce run n'a pas eu lieu, la ligne « shell root » de `bin-01` reste
**non prouvée**. Le rapport de jeu (`JEU-ETUDIANT-2026-11-05.md`) le dit
explicitement.

Un second workflow existe pour une mesure complète en une commande
(`mesurer-les-machines.yml`), mais GitHub n'autorise son lancement manuel que
lorsqu'il est présent sur la branche par défaut : il faudra le fusionner une
fois pour pouvoir l'utiliser, ou lancer `wordpress.yml`, qui fait le même
travail sur la branche de travail.

## 5. CI : ce qui a changé, et pourquoi

Avant : `ci.yml` et `wordpress.yml` se déclenchaient sur `push` (toutes
branches) et sur `pull_request`. Chaque pousse coûtait donc un run complet.

Après :

```yaml
on:
  push:
    branches: [ main ]   # une pousse sur une branche de travail ne lance rien
  workflow_dispatch:     # mesure manuelle, à la demande
```

- `pull_request` est retiré : la fusion ne déclenchera rien tant que ce n'est
  pas rebranché volontairement.
- La vérification PHP et les tests du dépôt ont été déplacés dans l'action
  partagée `.github/actions/preuves-machines`, pour qu'une seule commande
  mesure vraiment tout (la mesure manuelle hérite donc des contrôles de l'ancien
  CI).
- Au moment de la mise en service, il suffira de remettre
  `pull_request: branches: [ main ]` : un seul run, sur la demande de fusion.
